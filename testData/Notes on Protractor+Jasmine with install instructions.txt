1- beforeEach and beforeAll difference in Jasmine framework:

beforeEach() function is called before each spec (it block) i.e, code written inside beforeEach runs before every it block whereas,

beforeAll() function is called only once before all the specs (it block) inside the describe function() level are executed.

3- How to run ONLY 1 particular it block and ignore the rest??
Ans: Incase we have 20 it blocks in your spec file, but want to run only a particular it block. It's a Very Big NO and not feasible for prefixing all the 19 it blocks with x (i.e, xit)

Run any particular 'it block' by prefixing it with f (i.e, fit) where f stands for focussed.
describe('Protractor Typescript Demo', function() {

	fit('click operation', function() {
		console.log("Iam the only one who will run");
	});

	it('ignore test 1', function() {
		console.log("they have not prefixed me with f");
	});

	it('ignore test 2', function() {
		console.log("they have not prefixed me with f");
	});

6- How to run all all specs sequentially??
Ans: to run all specs 1 after another (non sequentially):
specs: ['specs/*'],

use suites

suites : {
	smoke: ['specs/loginSpec.js', 'specs/regSpec.js', 'specs/spec3.js'],
	
	regression: ['specs/reg1.js',
		   'specs/reg2.js']

	}

command to run the particular test:	protractor conf.js --suite smoke

A test suite is a collection of specs/testcases united by a common property, logic. For instance, you may have suites for different types of functionality of your application, homepage, search etc:

suites: {
  homepage: 'tests/e2e/homepage/**/*Spec.js',
  search: [
    'tests/e2e/contact_search/**/*Spec.js',
    'tests/e2e/venue_search/**/*Spec.js'
  ] 
},
And/or, you may have specs grouped into suites by the type of tests:

suites: {
  smoke: 'tests/e2e/smoke/*.js',
  performance: 'tests/e2e/performance/*.js'
},
Or, you may put all of your "regression" tests into a separate suite. Or, you can apply your own logic to group specs.


7- Why in protractor we have to resolve in promise? (Googled Qs.)
(Googled Ans.): Almost all Protractor functions work in this manner – returning a promise that resolves after an indeterminate amount of time, and upon resolving, triggering a function to handle the result.

8- Require vs Import:
The major difference between require and import , is that require will automatically scan node_modules folder to find modules, but import (which comes from ES6) won't.

9- browser.get() : It's used to go to the particular website , But it doesn't maintain the browser History and cookies so , we can't use forward and backward button , if we click on that , page will not get schedule. 

browser.navigate() : it's used to go to the particular website , but it maintains the browser history and cookies, so we can use forward and backward button to navigate between the pages during the coding of Testcase.

10- If any script running issue occurs with message like protractor.ps1 cannot be loaded because 	"running scripts is disabled on this system". This is because The PowerShell execution policy is default set to Restricted. We have to change the PowerShell execution policies to RemoteSigned.

Steps to follow for changing at system level:

(i) open poweshell for non-admin user by holding shift key + right click on windows button, select the "Windows PowerShell" option.
(ii) type "Set-ExecutionPolicy RemoteSigned" and hit enter
(iii) then type "a" key as specified below which stands for [A] Yes to All		
(iv) again hit enter 			and we are all set.

Steps to follow for changing at system level:
(i) open poweshell for non-admin user by holding shift key + right click on windows button, select the "Windows PowerShell" option.
(ii) type "Set-ExecutionPolicy RemoteSigned -Scope CurrentUser -Force"	(don't out double quotes or else it will defeat the purpose)
